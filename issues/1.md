### Summary
Design and implement a chat concept with models and interfaces for a system where participants can send and receive messages.

### Details
Based on discussions, the chat should:
- Allow 1 or more participants. (No explicit need for distinguishing group chats.)
- Support attributes for participants like `id`, `name`, `avatar`, and `role` (optional).
- Enable messages with attributes like `id`, `chatID`, `authorID`, `content`, and `timestampSent`.
- Keep chats flexible with attributes like `id`, `timestampCreated`, `participants`, `messages`, and optional metadata.

### Proposed Models
#### Chat
- `id`: Unique identifier.
- `participants`: List of participant IDs.
- `messages`: List of message IDs.
- `timestampCreated`: Creation time.
- `metadata`: Optional metadata (e.g., tags, name).

#### Participant
- `id`: Unique identifier.
- `name`: Display name.
- `avatarURL`: Avatar URL.
- `role`: Role (optional).

#### Message
- `id`: Unique identifier.
- `chatID`: Chat association.
- `authorID`: Author of the message.
- `content`: Text content.
- `timestampSent`: Time sent.
- `status`: Read/unread status (optional).

### Proposed Interfaces
#### Chat Management Service
- Manage chat lifecycle.
  - `createChat(participants: [Participant]): Chat`
  - `getChat(chatID: String): Chat?`
  - `deleteChat(chatID: String): Boolean`
  - `addParticipantToChat(chatId: String, participant: Participant): Boolean`
  - `removeParticipantFromChat(chatId: String, participantID: String): Boolean`

#### Messaging Service
- Handle chat messages.
  - `sendMessage(chatID: String, message: Message): Boolean`
  - `getMessages(chatID: String, paginationOptions: Object): [Message]`
  - `updateMessage(messageID: String, content: String): Message`
  - `deleteMessage(messageID: String): Boolean`

#### Participant Service
- Manage participants.
  - `createParticipant(name: String, avatarURL: String, role: String?): Participant`
  - `getParticipant(participantID: String): Participant`
  - `updateParticipant(participantID: String, details: Object): Participant`
  - `deleteParticipant(participantID: String): Boolean`

### Extensibility
- Scalable participant management.
- Optional metadata for chat organization.
